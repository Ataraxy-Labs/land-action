Run only the tests a change can reach.

A GitHub Action that records every file each test command reads, in the kernel, and skips the commands whose files didn't change. One file, GitHub's own runners, no account and no token.

Five speedups, borrowed from land

Each comes from land, the hosted version, and works on GitHub's free runners.

Skip by recorded reads

A command is carried only when every file, folder listing and installed package it read is byte for byte the same.

No path filters to write or keep up to date.

Each PR remembers

A pull request keeps its own record beside main's, so the next push carries what the last push proved.

An agent pushing fix after fix reruns only what each fix touched.

One unit per test file

split: files turns a pytest, vitest or jest line into one command per test file, and go test ./... into one per package.

Edit one module and only the files that read it run.

Rerun before blaming

A command that fails beside others is rerun alone before it is judged. One that flips is marked nondeterministic and never carried.

A flaky test shows up as flaky, not as your change.

Every core

Commands run in parallel, each with its own fresh home and temp folder, sized to the runner.

The whole runner is used without sharding anything.

Setup

Add one step after your dependencies are installed.

.github/workflows/land.yml
name: land
on: [pull_request, push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r requirements.txt
      - uses: Ataraxy-Labs/land-action@v1
        with:
          split: files
          run: |
            tests: pytest -q tests

When a command runs anyway

  • There is no green run on main yet, so the first run records.
  • Any file it read changed, appeared or disappeared.
  • It failed last time, or failed differently with the same files.
  • The recorder could not see everything it did.

Pull requests from forks work because nothing needs a secret. A pull request reads main's record and keeps its own, but never writes main's, so only your main branch decides what counts as green.

Limits

  • Linux runners only (ubuntu-*). GitLab.com's hosted runners work too, see the README.
  • Packages installed with pip install --user sit in your home folder, which the recorder doesn't watch. Use actions/setup-python or a system-wide install.
  • How much is skipped depends on how finely your tests are split. split: files is the easy way to get there.
